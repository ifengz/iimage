# newadaptor 开发提交审查

日期：2026-09-22。基线：`a557759`。范围：现有工作区全部项目改动及必要的提交阻断修复。
用户明确授权独立分支 `newadaptor`、自行 debug 和本地 commit；本轮不 push、不部署。

## 辩证结论

值得保存为可复现的开发分支，不应作为生产发布版本。

正方证据：旧官方 SDK 已退出当前依赖和调用入口，媒体传输统一通过
`newapi-media-client`；既有上传、OCR 入口、提示词编辑、批处理和结果下载仍保留。
独立目录也能安装、导入适配包、通过类型检查/测试/构建，提交不再依赖作者机器的兄弟项目。

反方证据：修复前直接“全部提交”会包含凭据形态的浏览器快照，并且
`file:../AIadapter/media-adapter` 使外部检出无法解析依赖。
本地测试通过不能反驳这两个问题。独立反方的修复前记录在
[.loop/commit-review-round1.json](.loop/commit-review-round1.json)。

## 已修复的提交阻断

1. **敏感快照隔离。** `.playwright-mcp/` 中 17 份 YAML 命中长 API-key 形态值。
   不验证密钥是否有效、不输出原文；该目录和已有 smoke 截图均被忽略，原文件留在本地。
   `.env` 类文件也不进入提交。没有替用户吊销密钥；若这些原始快照曾另行分享，应自行轮换相应密钥。
2. **依赖闭合。** 从干净的 AIadapter Git 快照构建原适配包，作为不可变 tgz 纳入 `vendor/`，
   保留来源标识、摘要和原许可证，锁文件记录完整性。未改上游适配器源码、没有本地分叉实现。
3. **文档迁移不丢失。** 忽略规则只针对根目录过程文件，`doc/core` 下已有迁移后的
   `task_plan.md`、`progress.md`、`findings.md` 一并纳入本次提交。历史内容没有删除。
4. **测试类型门槛恢复。** `tsconfig.test.json` 原先继承了排除所有测试文件的配置，
   实际报 `TS18003`。清空该排除项并提供统一 `typecheck` 命令。
5. **参考图编码边界。** 原压缩分支可能在降低质量后仍返回超限结果；无 canvas 路径
   也未计算 Base64 膨胀。现在完整 data URI 超过 2MiB 时失败且不发生成请求。
   两个新增回归用例在移除校验时失败，恢复校验后通过。
6. **当前状态与历史分开。** README 标明开发版本及独立安装方式；历史提案和流程记录
   加注释，不再把旧能力拦截或旧冒烟结果当成当前生产证明。

## 保留边界及后续生产门槛

- 这是本地开发直连，令牌仍在页面内存，尚无服务端持钥及应用访问控制。
- 保留当前开发版的未分类模型警示/手动尝试行为；这与早期提案的严格准入设计不同。
  未将这种差异伪装成已获生产批准；生产模型准入须重新确认，并核对真实网关能力。
- 本轮没有真实认证网关编辑、图片质量、浏览器完整生成/下载或 OCR 引擎运行验收。
  历史文生图、模型列表响应和截图不能替代这些门槛。
- 没有上线、没有远端分支发布，也没有执行或声称完成新的生产 OpenSpec apply/archive。
- 后续生产迁移需明确同源服务端、密钥与权限归属、下载目标限制、请求上限、脱敏错误，
  再以真实图片编辑、结果保存和页面回显完成验收。
